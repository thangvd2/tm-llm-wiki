# Provisioning resources using Configuration Layer Utility (CLU)

In this tutorial we will show how to provision Vault Payments resources using Configuration Layer Utility (CLU). Documentation of the tool can be found [here](/vault-payments/latest/EN/using_vault_payments/clu). We will provision four Vault Payments resources: a Parameter, Parameter Value, Instruction Flow and Instruction Flow Version.

## [](#creating_a_configuration_pack "Copy link to heading")Creating a Configuration Pack

CLU relies on configuration packs as its input. A configuration pack consists of a manifest file which lists the resources comprising the pack, the resource files defining the resources and optionally any additional external files which can be referenced by the resources, for example a Python source file.

The above snippet should be saved with the file name “manifest.yaml”. In the first line the version of the pack is specified, which in this case is “1.0.0”. The second line defines the name of the pack, in this case it is “tutorial\_test”. The same name should be re-used across multiple versions of the same configuration pack. Finally, the following lines list the configuration pack IDs of the resources in the pack.

All resources need to be defined in .resource.yaml or .resources.yaml files (the first extension should be used if the file contains a definition of just one resource, the second one when more resources are defined in the same file).

In our case, let’s create a “parameter.resources.yaml” file to define a Parameter and a corresponding Parameter Value resources, which later on will be referenced by our Instruction Flow Version. Please note that the file name can be anything, as long as it has an extension “.resource.yaml” or “.resources.yaml”. CLU tool will scan the directory and all subdirectories related to the path of the given manifest.yaml file and look for any files defining the resources, disregarding their names.

The above YAML file contains a list of resources, the first one of type `PARAMETER` and the second one of type `PARAMETER_VALUE`. For both resources we supplied the payload field which defines the API requests which will be made against [Vault Payments API](/vault-payments/latest/EN/api/payments_api/) to provision the resources. Please note that the top level `id` fields: `parameter_tutorial` and `parameter_value_tutorial` match the IDs referenced in the manifest.yaml file earlier. For the Parameter resource you can see that the ID of the resource which will be used in Vault Payments is specified inside of the payload, with the value `parameter-clu`. For the Parameter Value resource, the ID is not specified as it will be generated by Vault Payments. The ID of the “parent” Parameter resource on the other hand is referenced in the `parameter_id` field inside the `payload` with the value `parameter_clu`.

We should create another file for the Instruction Flow and Instruction Flow Version resources and save it as for example “instruction\_flow.resources.yaml”.

In this file we also define two resources, one of type `INSTRUCTION_FLOW` and the other one of type `INSTRUCTION_FLOW_VERSION`. Both resource definitions reference the configuration pack ID of the resource specified in the manifest.yaml file earlier. The first one references `instruction_flow_tutorial` and the second one `instruction_flow_version_tutorial`. The first resource definition in the `payload` field also defines the ID of the Instruction Flow which we want to use in Vault Payments, which is `instruction-flow-clu`. The second resource has a short payload just specifying the `code` field which actually references an external file `code/flow.py` using the `'@{}’` notation.
