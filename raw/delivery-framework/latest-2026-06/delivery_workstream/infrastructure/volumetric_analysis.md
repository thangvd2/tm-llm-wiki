# Volumetric Analysis

## [](#purpose "Copy link to heading")Purpose

This activity describes the process of producing statistics that relate to actual and expected request volumes and rates, as well as current and future data storage requirements.

Understanding account and posting volumes helps drive the selection and sizing of critical infrastructure components for the core banking solution. Deliverables include analysis reports outlining current transaction volumes, growth trends, peak usage times, and projections for future scalability requirements.

By way of example, a boutique bank with a low number of high value accounts could choose a database SKU or platform that has a lower maximum storage size than a tier 1 retail bank. Projected volumes are important and if these are expected to increase significantly over time then a database platform that allows for scaling without downtime should be selected over one that doesn’t.

Without this type of information being available, several risks emerge. These include both over-provisioning of resources which leads to unnecessary cost as well as under-provisioning resources which can cause performance issues during peak usage. Inaccurate estimation will also result in delays should the need arise to re-design or re-implement parts of the system to cope with unexpected transaction volumes.

## [](#predecessor_activities "Copy link to heading")Predecessor Activities

1.  Logs and metrics captured by IT Operations monitoring systems.
    
2.  Actual numbers of accounts and posting volumes provided by the business operations team.
    
3.  Projected account opening and posting volumes provided by the front office development / product teams.
    

## [](#guidance "Copy link to heading")Guidance

A volumetric analysis (existing and projected) for a core banking solution will take into consideration a number of factors, typically broken down into product families. Each product type has a different workload profile. For example, a typical current account may send and receive around a dozen debits and credits throughout the day, whereas a loan may only require an initial disbursement, daily accrual of interest, and a monthly repayment.

Teams will typically model financial products along the following dimensions to produce an estimate that can be used when sizing the different environment types.

1.  Product Type
    
2.  Transaction Types per Product Type
    
3.  Posting Batches per Transaction Type per Day/Month
    
4.  Posting Instructions per Posting Batch
    
5.  Re-balancing events per Posting Batch
    
6.  Active Accounts per Product Type
    

Actual weightings across different product types will depend very much on their relative complexity and will also vary from company to company.

Consider the following when undertaking this exercise:

-   *Identify Data Sources -* Review logs generated by the existing banking core to track user interactions, API calls, and system activities. Monitor network traffic to measure the volume of data exchanged between clients and servers. Use tools like Prometheus collect real-time metrics on system performance and database growth.
    
-   *Data Capture Methods -* Implement monitoring scripts and tools to automatically collect data from various sources at regular intervals. Conduct manual sampling during peak usage periods to capture accurate data on transaction volumes and request rates. Simulate heavy loads using load testing tools to measure system performance under stress.
    
-   *Avoid -* Incomplete data capture by ensuring all relevant data sources are included to prevent underestimating transaction volumes or request rates. Sampling bias by using random sampling techniques to avoid bias and ensure representative data collection. Seasonal variations by accounting for seasonal fluctuations in banking activities (for example, holidays, month-end transactions) to accurately assess system performance. Poor data integrity by verifying data accuracy and consistency to avoid misleading conclusions due to corrupted or incomplete data.
