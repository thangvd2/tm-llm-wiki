# Existing Infrastructure Build

## [](#purpose "Copy link to heading")Purpose

Assuming the existing infrastructure is hosted in a local data centre, there will be limitations as to what can be managed through code and automation versus what requires physical activity. In other words, a local deployment will involve moving and racking servers, and ensuring power, cooling and connectivity are available.

This is in contrast to a cloud deployment that will take advantage of Infrastructure as Code, pipelines, and APIs to configure and deploy the environment. Infrastructure as Code and automated deployment pipelines to manage each environment. This is discussed in more detail in the Target Infrastructure Build activity section.

There may also be a need to deploy new networking equipment to allow external connections to the cloud provider if the target architecture has decided on SaaS or public cloud/hybrid as the hosting model. As a result, the work may also involve configuring firewalls, VPNs, and other networking components to facilitate secure communication between the sites.

It also is imperative that any hardware being hosted outside of the cloud has been sized appropriately as it will be harder and more expensive to rectify mistakes later once the solution is in production.
